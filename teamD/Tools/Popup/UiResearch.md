# ポップアップUI調査・文言案

調査日: 2026-10-29。対象: 基本操作・ボス・ジャンプ台の3種類。

現行の説明には、プレイヤーが行う操作とキューブが自動で行う動作の混同がある。さらに、異なる内容をすべて「番号付きの説明3個」に収めたことで、重要度と意味の違いが見えにくくなっている。素材の装飾だけでは解消しない問題である。

この資料は調査結果と改稿案。画像、Prefab、ゲームの挙動は今回の調査では変更していない。以下の文言案・構成案は初見プレイテスト前の提案であり、理解しやすさが検証済みという意味ではない。

## 1. 調査方法と根拠の区別

- 現行3枚の実行時キャプチャ、タイトルロゴ、タイトルの開始ボタンを目視した。
- 移動・ドラッグ・矢印・ジャンプ・攻撃タイル・ボス体力・ゴール条件のC#を照合した。
- Microsoftのゲーム向けガイドライン、任天堂の開発者インタビューと公式操作説明シート、George FanのGDC講演スライド、Game Accessibility Guidelinesを読んだ。
- 「確認できた仕様」「資料に書かれている指針」「このゲームへの提案」を分けて記載した。他作品の操作やチュートリアルをこのゲームの仕様として扱わない。
- 新規ユーザーによる理解度調査は未実施。既存の解像度・入力テストは、読みやすさや理解度の保証にはならない。

## 2. 実装から確認したこと

| 項目 | 確認できた仕様 | 説明への影響 |
| --- | --- | --- |
| キューブ | 自動で前進する | プレイヤーへの指示は「タイルを動かす」「道をつなぐ」。手動移動や待機を前提にしない |
| タイル操作 | マウス左ボタンを押して選択し、押したまま移動、離して配置 | 「左ドラッグ」だけでなく、押す・動かす・離すを示す |
| 操作できないタイル | 固定グループと、キューブが使用中のマスを含むグループは移動不可 | 「すべてのタイルを自由に動かせる」とは説明しない |
| 矢印 | キューブがそのマスへ入ると進行方向が変わる | 何がきっかけで方向が変わるのかを明記する |
| カギとゴール | ステージ設定の必要数以上のカギを持つことが条件 | 「全部集める」と断定しない。必要数は既存のカギHUDと対応させる |
| 攻撃タイル | 有効な攻撃タイルに入ると攻撃。そのタイルは無効化され、他の攻撃タイルが有効化される | 同じタイルだけでは連続攻撃できない理由と、別のタイルを使う必要を伝える |
| ボス体力 | ダメージで体力が減り、ゼロで撃破イベントを発火 | 「緑のHP」より「ボスの体力」とバーへの指示が分かりやすい |
| ジャンプ台 | 踏むと自動でジャンプ。進行方向の2マス先が着地点。途中の1マスの効果は発動しない | 「1マス飛び越える」と「2マス先に着地」は同じルールとして図示する |
| ジャンプの着地 | 着地点のタイルを確認し、そのマスの効果を実行。タイルがなければ落下 | 「着地先にもタイルが必要」を残す。着地先に危険なタイルがあれば安全とは限らない |

## 4. 現行UIの具体的な問題

| 優先度 | 現在の表現・構成 | 問題 | 改善方針 |
| --- | --- | --- | --- |
| 高 | 「同じ場所で待たず」 | 自動前進のゲームで、待機を選べるように読める | 「別の攻撃タイルへ道をつなぐ」と実際の操作にする |
| 高 | 「タイルを左ドラッグ」 | 初心者が必要とする押すボタン、保持、離す操作を省略している | 左ボタンの図と短い入力説明を置く |
| 高 | 「赤い床を踏んで攻撃」「別の攻撃床へ向かう」 | 主語が省略され、キューブを直接移動させる指示にも読める | キューブが踏むと起こる結果と、プレイヤーが道を作る操作を分ける |
| 高 | 「矢印の向きに進路が変わる」 | 変わるタイミングが分からない | 「矢印を踏むと、その向きに進む」 |
| 高 | ジャンプの番号1・2・3と、本文の1マス・2マス | 図の番号と距離に別の意味がある。番号3は3マス先にも見えうる | 距離はマス目と軌道で示し、対象には名前を付ける |
| 中 | 「閉じて再開」＋×印 | ステージをまだ始めていない人に「再開」と案内。×は中止と受け取られる可能性もある | この開始時表示では「はじめる」。共通ボタンによる閉じる・進行開始の動作は維持 |
| 中 | 小見出し・タイトル・副題・右上カテゴリ・各カード・フッター | 同じ意味の文が繰り返され、次に読む場所が多い | 目的、入力・新ルール、重要な注意に絞る |
| 中 | 全ページ共通の三段カード | 基本操作・攻撃の循環・ジャンプ距離を、同じ種類の手順のように見せる | 共通化するのは外枠とボタン。説明の構造は内容に合わせる |
| 中 | 画像の番号と離れた説明欄の照合 | 対象を探し、番号を覚え、右側を読む往復が必要 | 短いラベルを対象の近くへ置く。画面を隠さない位置にする |
| 中 | 「灰色」「赤い」「黄色い」のみを頼りにした特定 | 色を区別しづらい人や別ステージの配色で分かりにくい | 実物・名前・形を合わせる |

「番号3が3マス先に見える」「×が中止に見える」は設計上の懸念であり、実際のユーザーがそう誤解したという調査結果ではない。

## 5. このゲームに合わせる見た目

既存の [タイトルロゴ](C:/HAL/Unity/hal-hackathon-internship/teamD/Assets/Title/Texture/TEX_Logo.png) は金色と青緑の角ばった立体文字。[開始ボタン](C:/HAL/Unity/hal-hackathon-internship/teamD/Assets/Title/Texture/TEX_Start_Button.png) はミント色の面、濃い側面、太い黒文字と白縁で「はじめる」と表示されている。これは実物を見て確認した特徴である。

現行ポップアップも角を落とした外枠は共有しているが、細かいカテゴリ、青い番号、大量の白いカード、フッター説明の組合せによって、ゲーム内の案内より説明資料に近く見える。これは本調査でのデザイン評価である。

次の制作では、ブロック状のシルエット、単純な面と影、太く読みやすい見出しを軸にする。本文まで立体文字にせず、読みやすい平面の文字を使う。開始ボタンの色・形・言葉はタイトル画面との共通性を優先する。金色を増やすこと自体を高品質の条件にしない。

画像生成は背景面・枠・ボタン素材の制作に使い、ゲーム画面はUnityの実撮影、説明文は検証した日本語を確定配置する。生成画像に実際と異なるゲームの配置や操作を描かせない。マウス図などの意味を持つ素材は、左ボタンの位置や輪郭の正確さを個別に確認する。

## 6. 3枚の文言・構成案

共通の書き方: 見出しは短い目的、本文は「です・ます」で統一。対象名は「青いキューブ」「タイル」「攻撃タイル」「ジャンプ台」「カギ」「ゴール」。数字は距離や個数として使い、説明項目の通し番号と混在させない。「しよう」は見出し程度にとどめ、各説明の末尾で繰り返さない。

### 基本操作

**タイトル:** タイルを動かして、道をつなごう

**入力説明:** マウスの左ボタンを押したまま動かし、離して置きます。

実ゲーム画面の対象の近くに置く説明:

- 青いキューブ: 「自動で進みます」
- 矢印のあるタイル: 「踏むと、その向きに進みます」
- カギとゴール: 「必要な数のカギを集めて、ゴールへ」

**注意:** 道が途切れると落下します。

**共通ボタン:** はじめる

構成: 入力説明をマウス図とタイル移動の矢印で最も目立たせる。青いキューブ・矢印・カギは実物に短い説明を添える。動かせる例を囲み、すべての床が動く印象を与えない。固定タイルや使用中タイルの制約を全部ここに詰め込むかは、初見テストでのつまずきから判断する。

### ボス

**タイトル:** 攻撃タイルでボスを倒そう

**仕組み:** キューブが赤い攻撃タイルを踏むと、ボスに攻撃できます。

**次の操作:** タイルを動かして、別の攻撃タイルへ道をつなぎます。

**繰り返す条件:** 別の攻撃タイルを踏むと、使ったタイルでまた攻撃できます。

**体力バーのラベル:** ボスの体力

**目標:** 体力をゼロにしよう

**共通ボタン:** はじめる

構成: 二つの攻撃タイルと「使ったタイルが再び使える」関係を中心に見せる。体力バーは小さな補助説明にする。既に知っているドラッグ操作を初回と同じ分量で再説明しない。具体的な攻略ルートを描き切らず、ルールだけが分かる図にする。撃破時の派手な発光より、攻撃の発生元と対象が見える撮影を優先する。

### ジャンプ台

**タイトル:** ジャンプ台で飛び越えよう

**操作:** トゲやすき間の手前に、ジャンプ台を置きます。

**仕組み:** 台を踏むと、自動で1マス飛び越えます。

**距離:** 着地するのは、進む向きの2マス先。

**注意:** 着地先にもタイルが必要です。

**図のラベル:** ジャンプ台／飛び越えるマス／着地する場所

**共通ボタン:** はじめる

構成: 実ゲーム画面に、踏み切りから着地までの軌道と着地点の輪郭を重ねる。進行方向を明示し、「進む方向に1マス通過して2マス先へ着地する」と見て分かるようにする。奥行き方向にトゲが並ぶ現在の撮影では、何個のトゲを飛ぶのか誤解される懸念があるため、進行方向の3マスが読み取れる画角を検討する。説明を三段の手順に分けない。

この文言をすべて同じ大きさの本文として並べるわけではない。操作は大きく、対象名は画像上、条件は補足にする。基本操作では操作の分かりやすさ、ボスでは攻撃の繰り返し条件、ジャンプでは位置関係がそれぞれ主役になる。

## 7. 次の仕上げで確認すること

1. 各文の対象・入力・条件・結果がコードと一致していること。カギ必要数やステージごとの外観は実シーンでも照合する。
2. 1枚の画像にした後でも、最初に行うことが一つ読み取れること。副題やフッターに重複する文を残さない。
3. 1280×720、1920×1080、4:3、横長で、切れないことに加えて本文を通常距離で読めること。文字の設定値だけで判定しない。
4. 色を頼らなくても、攻撃タイル・ジャンプ台・ゴールを写真とラベルから特定できること。
5. 開始ボタンを押す前は停止、押した後は操作可能で、クリックが背後のタイルへ抜けないこと。
6. 初見の人に説明を補足せず操作してもらい、最初に迷った場所を記録する。基本操作は「自力でタイルを移動・配置できる」、ボスは「同じ攻撃タイルだけでは繰り返せないと理解して別のタイルを使える」、ジャンプは「着地点を正しく予測できる」を見る。

固定画像では文字だけの拡大や読み上げ対応に制約がある。外部ガイドラインを参考にすることと、アクセシビリティに適合した製品であることは別である。前回の動作・表示チェックだけを根拠に「製品版レベル」と評価するのは不十分だった。
